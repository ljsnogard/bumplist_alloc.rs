# PageState 与可变的页内起始地址

- 状态：**已实施（2026-11-19 19:00）**
- 相关代码：[`src/page_.rs`](../src/page_.rs)、[`src/alloc_.rs`](../src/alloc_.rs)
- 目标：为后续「单次分配超过页大小、由同一个 `BumpListAlloc<A>` 管理不同大小页」做
  准备；本次**不改变外部 API**，只改内部 PageState / 块布局 / 空页判定。

## PageState

四个 `u16`，`#[repr(C)]`，总大小仍是 8 字节：

```rust
pub(crate) struct PageState {
    base_: CellIndex,     // 首个可分配 cell 的页内绝对下标
    cells_: CellIndex,    // 从 base_ 起可分配的 cell 数
    used_: CellIndex,     // 相对 base_ 的 bump 偏移
    returned_: CellIndex, // 相对 base_ 的已归还 cell 数
}
```

- `base_` / `cells_` 是页的初始参数，不同页可以不同（`Page::init_in_place_` 现在接受
  `first_cell`）；
- 整页是否全部归还：`returned_ == used_`。空页复用后两者归零，`base_` / `cells_`
  保持不变；
- 不再有 `live_` / `first_` / `last_`，`PageList` 也不再需要 `tail_empty_`。

## 块布局与块链

分配时块头放在当前 bump 位置 `base_ + used_`，用户数据在块头之后按
`Layout::align()` 对齐；块头与用户块之间的 padding 属于本块。

`BlockHeader`：

- `order_flags_`：低 15 位是自身页内绝对 cell 下标，最高位是释放标记；
- `next_free_`：本块末尾（下一块头 / bump 末尾）的绝对 cell 下标。

因此块链天然连续：从 `base_` 沿 `next_free_` 走到 `base_ + used_` 即可，不需要
`first_` / `last_`，也不需要回填前一块头。释放时：

```text
span = next_free_ - header_cell;
returned_ += span;
if returned_ == used_ { used_ = 0; returned_ = 0; }
```

块链扫描（debug / 析构警告）同时校验 `order_flags`、`next_free` 范围，以及所有已释放
块的 span 之和等于 `returned_`。

### 对齐 padding 与 locator

块头放在 bump 位置后，用户数据可能不紧邻块头（对齐 padding）。为了保持
`Allocator::deallocate` / `Box::drop` 从用户指针 O(1) 反推块头，在有 padding 时把
紧邻用户块的 padding cell 写成 locator：

```text
locator = LOCATOR_BIT | distance
distance = (user_cell - 1) - header_cell
```

`LOCATOR_BIT` 是最高位。活跃块头的 `order_flags_` 最高位为 0，因此：

- 紧邻用户块的 cell 最高位为 0：它就是活跃块头，按原公式反推页首；
- 最高位为 1：它是 locator，先减去 `distance` 找到块头，再读取块头 order 反推页首。

`Page::locate_block_` 封装了这段逻辑；`Allocator::deallocate` 与 `Box` 都改用它。
没有 padding 时没有额外 cell 开销；有 padding 时 locator 复用本来就要消耗的 padding
cell。

## 空页判定与 PageList 清理

`PageList` 删除了 `tail_empty_: bool`。`cleanup_empty_page_` 现在：

1. 先取 `list_lock_`，再取被清理页的页锁，重新确认 `returned_ == used_`
   （期间可能被 tail 分配复用）；
2. 如果它已经是 `tail_`，保留复用；
3. 否则摘链，并在持有链表锁时锁住原 `tail_` 读取其 `empty_locked_()`；
4. 原 tail 为空则归还本页；否则把本页挪到 tail 复用。

锁顺序固定为「链表锁 → 页锁」。分配路径只在持有链表锁时用 `try_lock` 取页锁；
归还路径在调用清理前已经释放页锁，因此不会形成 ABBA 死锁。

## 可变起始地址与后续大页

`Page::init_in_place_` 现在接受 `first_cell`，`PageState.cells_` 按页计算容量，
`Page::try_alloc_` / `release_` / `scan_chain_` 都只依赖 `PageState`，不再需要
`page_cells` 参数。

本次 `BumpListCore::create_page_` 仍然传 `Page::CELLS`，即普通页行为不变；
`fits_page_` 也仍按当前固定页大小做保守检查。后续支持大页时需要：

- 按请求页大小申请 backing 内存，并为该页选择 `first_cell`；
- 把「页大小」与 `fits_page_` 的判断从固定 `page_size_` 扩展到按页/按请求；
- 不同大小的页可以继续用同一套 `PageState` / 块链 / locator 算法管理。

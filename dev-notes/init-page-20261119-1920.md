# 第一页元数据与单指针 `BumpListAlloc`

- 状态：**已实施（2026-11-19 19:20）**
- 分支：`feat/move-safety`
- 相关代码：[`src/init_page_.rs`](../src/init_page_.rs)、[`src/alloc_.rs`](../src/alloc_.rs)、
  [`src/page_.rs`](../src/page_.rs)
- 目标：把 `BumpListAlloc<A>` 收缩成一个指针，并让它在创建 Page 之后仍可安全移动。

## 背景

上一提交（`03f5059`）让 `Page` 支持可变的 `PageState.base_` / `cells_`，因此第一页不必
从 `Page::CELLS` 开始分配：`Page` 头之后可以再放 `BumpListCore` 与底层分配器 `A`。本次
改造把“分配器状态”整体搬进第一页的内存，`BumpListAlloc` 只保留一个
`NonNull<InitPage<A>>`。

旧设计的两点代价：

1. `BumpListAlloc` 内部直接内联 `BumpListCore` 与 `A`；Page 的 owner 指向内联 Core，
   所以创建第一个 Page 后句柄不能移动；
2. Core 保存两个单态化函数指针与一个“整分配器自指针”，每次分配 / 归还前用
   `offset_of!` 从自指针找回 `A`。

## 布局

```text
InitPage<A>（位于 page_size 字节的第一页起始处）
├── Page                     // 必须在偏移 0
├── ... padding ...
├── BumpListCore             // 非泛型；Page.owner_ 指向它
├── MaybeUninit<A>           // 底层分配器
└── ... 第一页剩余可分配区域 ...
```

`InitPage` 使用 `#[repr(C)]`，`Page` 是第一个字段；因此 `NonNull<InitPage<A>>` 与
`NonNull<Page>` 指向同一地址。第一页的 `PageState.base_ = ceil(size_of::<InitPage<A>>() / P)`，
普通页仍是 `Page::CELLS`。这两类页都由同一套 `PageState` / 块链 / locator 算法管理。

`BumpListAlloc<A>`：

```rust
#[repr(transparent)]
pub struct BumpListAlloc<A: Allocator + Send = Global> {
    page_: NonNull<InitPage<A>>,
    _owns_a_: PhantomData<A>, // 零大小，用于 dropck/方差
}
```

`#[repr(transparent)]` 保证与 `NonNull` 同布局；`PhantomData<A>` 明确句柄拥有第一页中的
`A`，让 dropck 知道析构会访问 `A`。

## 构造

`new_in(alloc, page_size)` 现在立即申请第一页：

1. 校验页大小：平台支持、普通页至少能放 `Page::CELLS + 2` 个 cell；
2. 校验第一页元数据：`ceil(size_of::<InitPage<A>>() / P) + 2 <= page_cells`；
3. 用 `Layout::from_size_align(page_size.bytes(), align_of::<InitPage<A>>())` 申请；
4. 原地写入：`Page`（owner 指向 Core 地址）→ `A` → `BumpListCore`；
5. Core 的 backing 字段在 `A` 写入之后建立，指向第一页里的 `MaybeUninit<A>` 槽。

新增两个错误变体（`BumpListAllocError` 已有 `#[non_exhaustive]`）：

- `PageSizeTooSmallForAllocator { page_size }`：第一页放不下元数据 + 最小分配块；
- `InitPageAllocationFailed { page_size }`：底层分配器无法提供第一页。

因此构造从“只可能因页大小失败”变成“可能因页大小或底层分配失败”。这是把状态放进
第一页、并保持单指针句柄的必然结果；用惰性首分配无法做到，因为页大小也必须存在某个
稳定位置，而句柄只有一个指针。

## `BumpListCore` 的简化

### 删除 `page_cells_` / `page_bytes_`

两者均可由 `page_size_: PageSize` 直接得到：

- `page_cells` = `page_size_.cells()`；
- `page_bytes` = `page_size_.bytes()`。

它们是旧实现为了少一次 match 而缓存的；现在 Core 位于第一页，第一页的容量由自己的
`PageState.cells_` 表达，普通页的容量由 `page_size_` 表达，缓存字段没有额外语义，删除。

### 函数指针 → `NonNull<dyn Allocator>`

旧 Core 保存：

```text
backing_alloc_: fn(*const (), Layout) -> ...
backing_dealloc_: fn(*const (), NonNull<u8>, Layout)
self_ptr_: AtomicPtr<()>
```

新 Core 保存：

```rust
backing_: NonNull<dyn Allocator>,
```

`core::alloc::Allocator` 是 object-safe 的（没有泛型方法；`grow` / `shrink` 等都有默认
实现），因此可以直接转发 `allocate` / `deallocate`。

- fat 指针为两个指针宽度，与旧的两个函数指针相同；
- 不再需要 `self_ptr_`，Core 净减少一个指针宽度，也消除了“每次操作前刷新自指针”的
  步骤；
- 不需要为每个 Page 保存函数指针，因为 owner 仍指向唯一的 Core。

为什么字段是 `NonNull<dyn Allocator>` 而不是 `&'static dyn Allocator`：

- `A` 可能带非 `'static` 的借用，而 `BumpListCore` 是非泛型类型，无法在字段类型上命名
  这个生命周期；
- 我们只需要在持锁调用期间临时 materialize `&dyn Allocator`，不需要在 Core 里长期保存
  一个引用；
- 原始 fat 指针允许在析构时把 `A` 移出第一页而不留下“悬垂引用”。构造时把
  `&dyn Allocator` 的生命周期擦除成 `'static`，只作为 vtable 载体；该指针不离开 crate
  内部，Core 也总是先于 `A` 被销毁。

`A: Send` 仍然足够：所有对 `A` 的调用由 backing lock 串行化，因此不要求 `A: Sync`。

## 第一页的特殊处理

第一页（root）是分配器元数据页，不能像普通页那样归还：

- root 始终挂在链表里，`dealloc_page_` 有 `debug_assert` 禁止归还它；
- root 的可用容量小于普通页；
- 空页策略从“最多缓存一个空 tail”调整为“root 永久保留，此外最多一个空页”：
  - root 变空：若 tail 是另一个空页，先摘链归还它，再把 root 挪到 tail；
  - 普通页变空且 root 已空：不能再保留第二个空页，直接摘链归还该普通页；
  - 普通页变空且 root 非空：沿用旧策略（tail 空则保留，否则挪到 tail）；
  - 不在本 allocator 链表上的 Page（单元测试辅助对象）直接跳过，不参与回收。

分配路径增加一个特例：空 root 放不下时，如果失败原因是“root 容量不足”（请求的
`块头 + 数据 cell` 超过 root 的 `cells_`），则追加普通页；如果只是对齐/地址原因放不下，
仍按旧规则返回 `AllocError`，避免无意义地追加新页。这样小请求可以继续复用 root，大请求
可以落到普通页。

## 析构顺序

`BumpListAlloc::drop` 调用 `InitPage::drop_in_place_`：

1. 用第一页里仍然存活的 `A` 归还所有**非 root** 页（Core 的 `free_non_root_pages_`）；
2. `drop_in_place(core)`：销毁 Core，结束 backing 对 `A` 的自引用；
3. `ptr::read` 把 `A` 从第一页的 `MaybeUninit<A>` 槽移到栈上；
4. 用栈上的 `A` 归还第一页本身（布局 size = page_size，align = `align_of::<InitPage<A>>()`）；
5. 销毁栈上的 `A`。

关键点：归还第一页时，`A` 已经不在被归还的内存里。旧设计不需要处理这一点，因为 `A` 在
`BumpListAlloc` 内联、由栈 / 外层分配负责；新设计必须显式移出，否则会形成“用自己
释放包含自己的内存”的自引用析构。

## 为什么不是其他方案

- **把 `A` 放在单独的堆分配里**：`BumpListAlloc` 仍是一个指针，但多一次分配；且 Core
  仍然需要指向 `A`，没有解决生命周期 / 析构问题。
- **`Box<A>`**：同上；还会把 `A` 的地址稳定性和第一页绑定变得不必要。
- **让 `BumpListCore<A>` 泛型化**：Page 的 owner 是 `NonNull<BumpListCore>`，泛型化后
  Page 需要类型擦除或携带 vtable；Core 在 Page owner 上的非泛型性质会被破坏。
- **保留 `self_ptr_` + 函数指针**：能实现移动安全（第一页地址稳定），但 Core 更大，
  且每次分配都要刷新 / 读取自指针，不如直接存 `dyn` vtable。
- **把 `BumpListAlloc` 做成 `enum { Uninit(PageSize), Init(NonNull<...>) }`**：不再是单
  指针，且零尺寸分配仍需初始化路径；当前设计接受构造时立即申请第一页。

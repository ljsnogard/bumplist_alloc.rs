# `Box` API 补齐（std `Box<T>` 对齐）

- 状态：**已实施（2026-11-19 13:50 更新：加入 Send/Sync）**
- 前置讨论：`BumpListBox` 改名为 `Box`、`Box` 独立于 `denco_arena` 特性
- 相关代码：[`src/boxed_.rs`](../src/boxed_.rs)、[`tests/boxed_.rs`](../tests/boxed_.rs)

## 背景

`Box<'a, T>` 是 arena 里一块 `T` 的独占句柄，只保存 `NonNull<T>` 与
`PhantomData<&'a T>`，不保存分配器引用。它已有的能力是 `Deref` / `DerefMut` /
`TrBoxed` / `TrUnique` / `Drop`。本轮把它向 `std::boxed::Box<T>` 的常用 API 靠拢。

## 放弃 `TrAllocBy`

`TrAllocBy::mem_alloc(&self) -> &Self::Alloc` 要求 `Box` 里已经存在一个 `Alloc`
值可供借用。`Box` 只有块指针：

- `Page::owner_` 只能给出非泛型的 `&BumpListCore`；Core 里的整分配器指针是
  `AtomicPtr<()>`，底层分配器 `A` 已被类型擦除；
- 即便用 `offset_of!` 猜出 `BumpListAlloc<A>`，猜错 `A` 就是类型混淆；猜对也需要把
  `A` 放回 `Box` 的类型参数或字段；
- 零尺寸 `T` 没有 `Page`/`BlockHeader`，任何“从页里找分配器”的方案都覆盖不了它。

因此改为：不实现 `TrAllocBy`，只补齐不需要分配器句柄的 std `Box` 能力。

## 本轮实现

### 基础转发

- `AsRef` / `AsMut` / `Borrow` / `BorrowMut`
- `Debug` / `Display` / `Binary` / `Octal` / `LowerHex` / `UpperHex` / `LowerExp` /
  `UpperExp` / `Pointer`
- `PartialEq` / `Eq` / `PartialOrd` / `Ord` / `Hash`
- `Hasher`（转发全部稳定的 `write_*` 方法）
- 显式 `Unpin`：`Box<T>` 无条件 `Unpin`，与 std `Box<T>` 一致；`Box::into_pin`
  因此可以用 `Pin::new_unchecked`。

### 裸指针、泄漏与 Pin

- 关联函数：`as_ptr` / `as_mut_ptr` / `as_non_null`、`into_raw` / `from_raw`、
  `into_non_null` / `from_non_null`、`leak`、`into_pin`
- `From<Box<'a, T>> for Pin<Box<'a, T>>`（`Pin` 是 `#[fundamental]`，孤儿规则允许）
- `leak` 返回 `&'a mut T`，受 arena 借期约束；块不归还，随 arena 析构释放。
  注意：从 `leak` 返回的 `&mut T` 再转回 `Box` 不能访问 `T` 之前的 `BlockHeader`
  （Stacked Borrows 下该引用的 provenance 只覆盖 `T`）；测试里是在泄漏前用
  `as_non_null` 保存指针来回收。

### `Clone`

`impl<'a, T: Clone> Clone for Box<'a, T>`（`T` 隐含 `Sized`；不支持 `Box<[T]>` 的 `Clone`）：

- 非零尺寸：先克隆 `T`，再从 `Page::owner_` 取 `BumpListCore`，调用
  `Core::allocate_` 在同一 arena 分配新块，写入克隆值；
- 零尺寸：没有块头/页，直接复用原句柄的对齐悬垂地址；克隆值的 `Drop` 交给新
  `Box` 的 `drop_in_place`，因此先 `mem::forget` 克隆值，保证恰好析构一次；
- 分配失败按 std `Box` 的 OOM 语义调用 `handle_alloc_error`（abort）。

安全不变量：调用 `allocate_` 需要 `self_ptr_` 指向当前 arena；能拿到 `Box` 说明创建
它的分配刚刷新过 `self_ptr_`，且 `'a` 借住 arena，期间 arena 不会移动/析构。该实现
沿用现有“首个 Page 后不移动 arena”的地址稳定性约定。

### `Iterator` / `Future` / `Error`

- `Iterator` / `DoubleEndedIterator` / `ExactSizeIterator` / `FusedIterator`
- `Future`（要求 `F: Future + Unpin`）
- `Error`（转发 `source`）

### `T: ?Sized` 与 `CoerceUnsized`

- `Box<'a, T: ?Sized>`；`Drop` 用 `size_of_val` 判断零尺寸，`locate_page_` 先丢弃
  元数据再读块头；
- `impl<'a, T: ?Sized + Unsize<U>, U: ?Sized> CoerceUnsized<Box<'a, U>> for Box<'a, T>`
  支持 `Box<'a, Concrete>` → `Box<'a, dyn Trait>`；需要
  `#![feature(coerce_unsized, unsize)]`（本 crate 已是 nightly）。

### `Send` / `Sync`

先澄清一个易错点：`&'a BumpListAlloc<A>` 并不是无条件 `Send + Sync`。`&T: Send` 与
`&T: Sync` 都要求 `T: Sync`，而旧实现的 `BumpListAlloc<A>: Sync` 要求 `A: Sync`。

本轮选择的路线是**用锁把对 A 的访问串行化，从而只要求 `A: Send`**：

- `BumpListAlloc<A>` 的类型约束改为 `A: Allocator + Send`（默认 `Global` 满足）；
- `BumpListCore` 新增 `backing_lock_`，`create_page_` / `dealloc_page_` 中所有对 A 的
  `allocate` / `deallocate` 调用都在该锁内执行；
- `unsafe impl<A: Allocator + Send> Sync for BumpListAlloc<A>`：A 被 arena 独占，
  `A: Send` 允许它在任意线程上被独占使用，锁保证不会并发调用，因此不要求 `A: Sync`；
- `Box` 不携带 A，按 T 实现：
  - `unsafe impl<T: ?Sized + Send> Send for Box<'_, T>`
  - `unsafe impl<T: ?Sized + Sync> Sync for Box<'_, T>`
  - 安全依据：所有安全构造出的 Box 都来自 `BumpListAlloc<A: Send>`；`'a` 保证 arena
    存活；跨线程的块归还 / Clone 只经过被 `backing_lock_` 串行化的 A 调用。

注意：锁只能把要求从 `A: Sync` 降到 `A: Send`，不能降到“任意 A”。`A: !Send`
（例如内部持有 `Rc` 的分配器）仍不能用于 `BumpListAlloc`；需要 trait object 时要写
`&(dyn Allocator + Sync)`，`&dyn Allocator` 本身不是 `Send`/`Sync`。

这同时意味着 `BumpListAlloc<A>` 的公开约束收紧为 `A: Send`，而 `&BumpListAlloc<A>`
对所有可构造的 A 都是 `Send + Sync`。

## 明确不做

| API | 原因 |
|---|---|
| `Box::new` / `Box::pin` / `new_uninit*` / `try_new*` / `new_in` | 需要 arena 上下文，`Box` 不知道用哪个 arena |
| `Default` / `From<T>` | 没有 `&self` 或 arena 参数可定位；`Clone` 可以是因为有 `&self` |
| `allocator` / `into_raw_with_allocator` / `from_raw_in` | 不保存分配器句柄 |
| `Fn*` / `Coroutine` / `AsyncIterator` / `DispatchFromDyn` / `DerefPure` | nightly 内部特性或不适合 arena 句柄 |
| `std::io::{Read, Write, Seek, BufRead}` | 本轮未纳入范围，可在 `std` 特性下另做 |
